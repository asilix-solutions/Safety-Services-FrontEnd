1. Introduction

1.1 Purpose

This Software Requirements Specification (SRS) describes the functional and
non-functional requirements for the Safety Services & Licensing
Management System -- a centralized cloud (SaaS) platform that manages
the operations of technical safety and licensing companies. It governs
licensing-request processing, automated activity/area-based routing,
centralized field execution and procurement, document and signature
authentication, and per-tenant isolation.

1.2 Product Scope

The platform provides an isolated workspace per subscribed safety company
(tenant), an automated rule engine that classifies licensing requests by
activity type and facility area, a centralized operations and procurement
portal where the operations officer records all field activity (material
invoices, field labor governance, technical inspection reports), and an
interactive client portal for service selection, facility data entry, file uploads,
and live tracking by Job Number -- protecting the company's financial and
legal records. In the current MVP, all field operations are performed through
the responsive web browser portal rather than a native mobile application.

2. Overall Description

2.1 Product Perspective

The system is an integrated operational and administrative
environment connecting client-facing portals with internal control
panels for sales agents, consulting engineers, and the central
operations & projects officer. All interfaces synchronize in real time to
exchange data and update request, procurement, and obstacle-log
states simultaneously.

2.2 Product Functions

At a high level, the system will:

    Provision and isolate a dedicated tenant environment, custom
       subdomain, and branding per subscribed company.

    Authenticate users with TOTP multi-factor authentication and
       role-based access control.

    Capture client intake (CR/700 number, built-up area, GPS, documents,
       blueprints).

    Automatically route requests by area thresholds and ISIC activity
       hazard bands.

    Manage consulting workspace, blueprint review, and three specialized
       technical reports.

                                                                                                                2
    Run centralized web-based field execution: project silos,
       procurement/VAT, labor governance, obstacle logs, signature capture,
       recurring maintenance scheduling.

    Provide tracking, internal chat, profitability analytics, BI dashboards,
       and SLA scorecards.

    Enforce non-functional security, performance, and integration
       requirements.

2.3 User Classes and Characteristics

    Super Admin: Holds top-level authority to manage subscribed safety
       companies, review packages, and monitor overall platform
       performance.

    Company Admin: Controls their own safety company's options,
       manages staff accounts, and views profitability analytics and
       operational/financial reports.

    Consulting Engineer: Receives new licensing/contract requests,
       reviews uploaded data, studies blueprints, manages and generates
       quotes, assigns inspection agents, and prepares/approves the three
       specialized technical reports.

    Operations & Projects Officer: The pivotal field party; receives work
       orders on approval, manages item procurement, records tax invoices,
       schedules and enters field labor data and wages, documents

                                                                                                                3
       inspection/obstacle reports, and closes tickets with client
       signature/stamp photos.
    Sales Agent: Adds target clients in the field and tracks the sales
       pipeline from request to approval, with commission isolation.
    Client: Uses services by filling forms, reviewing quotes, and tracking
       the project and completion photos live via their Job Number.

2.4 Operating Environment

The system runs in modern web browsers on desktop and
mobile-responsive views; field execution is performed through the
responsive web portal. It uses a backend server, relational database, object
storage, and Redis cache; all communication via HTTPS/TLS 1.3.

2.5 Design and Implementation Constraints

    Multi-tenant data isolation enforced at the query level.
    ZATCA-compliant 15% VAT partitioning for taxable items.
    Architecture must be integration-ready for future Civil Defense /

       government portals (RESTful/GraphQL + OpenAPI).
    Field workflows delivered via responsive web (no native mobile app in

       the current MVP).

3. External Interface Requirements

3.1 User Interfaces

tenant-branded portals with dynamic colors and logos injected on

3.2 Software Interfaces

Integration with a transactional Email provider, Google Maps for facility
geolocation, object storage (AWS S3 / GCP Storage), and Redis Pub/Sub for

All traffic over HTTPS/TLS 1.3; WebSocket channels for low-latency chat;
real-time webhooks for obstacle/status broadcasting.

   5. Use Cases

    UC-01 -- New Licensing Request (Automated Routing)

Actors: Primary -- Client; Secondary -- Rule Engine, Consulting Engineer Pre-conditions:
Client has accessed the tenant portal via the custom subdomain; the system is online.

Main Flow:

    1. Client opens the company portal via the custom subdomain.
    2. Client fills the intake wizard: activity name and type, ISIC code, CR/700 number

         (10 digits), actual built-up area (m²), land plot number and location description,
         GPS coordinates, current safety tools, and uploads (building permit or deed).
    3. Client clicks "Submit Request."
    4. System reads the Area field and Activity field and routes automatically:

              Area < 150 m²  Fast-Track / Basic Safety Hardware  customer-service
                  queue for an instant quote and immediate technical report on payment.
                                                                                                              21
              150­1000 m²  Mandatory periodic maintenance contract  schedule a
                  field inspection and push to the sales pipeline.

              1000 m²  Full engineering blueprint execution  open a consulting
                  ticket.
                  

    5. If the activity is High-Hazard (buffet/kitchen, gas extensions,
         flammable-materials workshop), the system severs fast-track regardless of area
         and forces a non-instant report under Comprehensive Engineering Review.

    6. System creates the ticket and generates a Job Number with a live tracking
         timeline.

Post-Conditions: Request is classified, routed to the correct track, and visible to the
client via Job Number.

Alternate Flows:

     AF-1 Invalid CR/700: Number isn't exactly 10 digits  show validation error 
         client corrects and resubmits.

     AF-2 Invalid Area: Negative or textual value  reject with field error.

Exceptions:

     EX-1 Blueprint Upload Rejected: Wrong format or > 50MB  reject server-side
         with descriptive error; no partial storage.

    UC-02 -- Login & Multi-Factor Authentication

Actors: Super Admin, Company Admin, Consulting Engineer, Operations Officer, Sales
Agent, Client Pre-conditions: User account exists; user is on the login page.

                                                                                                              22
Main Flow:

    1. User enters email/phone and password.
    2. System verifies the password via secure hash comparison.
    3. System checks account status (active, not suspended).
    4. If the account is flagged for mandatory MFA (admin, operations, cash), system

         presents the 6-digit TOTP challenge.
    5. System validates the TOTP and creates a session/JWT.
    6. System applies RBAC and redirects to the appropriate workspace.

Post-Conditions: User is authenticated within their role scope; field-worker responses
exclude profitability/billing payloads.

Alternate Flows:

     AF-1 Invalid Credentials: Show "Invalid email/phone or password"; allow retry or
         password reset.

     AF-2 Suspended Account: Deny access with a support message.
     AF-3 MFA Failure: Reject the token; allow re-entry or backup-seed recovery.

    UC-03 -- Field Execution & Project Closure

Actors: Primary -- Operations & Projects Officer, Field Technician; Secondary --
Consulting Engineer Pre-conditions: Quote is approved and first payment confirmed; a
project was auto-provisioned into 3 silos.

Main Flow:

    1. The project appears in the operations officer's web workspace, split into Alarm,
         Suppression, and Ventilation silos.

                                                                                                              23
2. Officer records procurement: enters supplier name, purchase item
    (Alarm/Suppression/Ventilation), and invoice value.

3. Officer sets invoice type:
          Taxable  system forces entry of pre-tax value and the 15% tax amount in
             an isolated ZATCA-refund field.
          Non-taxable  tax field is zeroed and disabled.

4. System blocks saving any field invoice without a live browser-camera photo of the
    original paper invoice (EXIF-verified).

5. Officer enters field labor: name, field role, and legal category -- Internal (cost
    zeroed) or Outsource (mandatory agreed wage entry).

6. On cash payment to outsource labor, officer clicks "Confirm Final Outsource Labor
    Settlement"; system logs timestamp, IP, and geo-tag to a WORM store.

7. Officer uploads live installation photos that appear instantly in the client portal
    and admin panel.

8. On obstacles, officer logs a description with live photos via the web view and
    clicks "Broadcast"; webhooks alert management and update the client tracker and
    chat room.

9. After installation, officer runs a full operational test, documents commissioning
    metrics with proof photos, and sets status to "Ready for Final Inspection."

10.To close: the client signs and stamps the inspection report by hand; the officer
    uploads it via the responsive web interface (with an HTML5 canvas signature pad
    option) as the mandatory closure lock; the snapshot binds as an unalterable
    attachment.

11.System notifies the consulting engineer to approve the official technical reports
    toward certificate issuance.

Post-Conditions: Project is closed with legal proof of execution; net margin is
recomputed from validated expenses.
Alternate Flows:

     AF-1 Missing Subsystem Classification: Expense submission rejected to protect
         gross-margin calculations.

     AF-2 Stale Receipt Photo: EXIF check fails (library upload, not live)  reject.
     AF-3 Closure Without Signed Upload: Complete-Ticket stays disabled until the

         signed/stamped document is uploaded.
Exceptions:

     EX-1 Upload Service Error: Network/storage failure during photo upload  show
         retry message, preserve form data, do not mark step complete.
